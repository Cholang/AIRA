버튼 배치 시안 — 표준 버튼 단어로 바꿨을 때

버튼을 "재시도 · 이대로 진행 · 건너뛰기 · 완료"처럼 짧은 표준 단어로 바꾸면, 누르면 무엇이 되는지를 버튼 밖에서 말해야 합니다. 그 설명을 어디에 둘지 세 가지를 같은 상황으로 비교합니다. 위에서 버튼 수를 바꿔 보세요. 문구는 실제 상황(극축 정렬 끝 · 자동초점 실패 · 포커서 0점 실패)입니다.

버튼 수 테마

A · 지금 배치 유지설명은 왼쪽 위 안내 문장, 버튼은 가운데 아래

  • 지금 앱 그대로 — 고칠 것이 문구뿐
  • "재시도가 무엇을 하는지"가 화면 맨 위에 있어 눈이 위↔아래를 오간다
  • 주 버튼 자리가 버튼 수와 상관없이 늘 가운데
  • 버튼마다 설명을 넣으면 안내 문장이 세 줄을 넘어 길어진다(3개일 때)

B · 65% 설명 | 35% 버튼사용자 안 — 설명은 오른쪽 정렬, 버튼은 왼쪽 정렬(주 버튼이 맨 앞), 둘이 가운데 선에서 만난다

  • 설명 끝과 버튼이 바로 붙어 읽고 바로 누른다
  • 주 버튼 자리가 가운데에서 오른쪽(65% 선)으로 옮겨진다 — 지금 손이 외운 자리와 다름
  • 주 버튼 자리가 버튼 수와 상관없이 같다(65% 선 바로 오른쪽) · 적도의 홈 · 아이라 종료와도 떨어져 있다
  • 오른쪽 정렬 글은 줄마다 시작점이 달라 두 줄째를 읽기가 조금 힘들다 · 버튼별 설명은 "재시도" 같은 이름표가 필요

C · 버튼 아래 한 줄 설명제안 — 지금 자리 그대로, 버튼마다 "누르면 무엇이 되는지"를 바로 밑에

  • 설명이 버튼 바로 밑 — 고를 때 눈이 움직이지 않는다
  • 버튼 줄 높이가 늘어난다(설명 두 줄 자리를 늘 확보 → 측정값이 약 45px 위로)
  • 주 버튼 자리 · 보조 버튼 자리가 지금과 같다(손이 외운 자리 유지)
  • 설명이 버튼마다 한 줄 안에 들어가야 한다(15자 안팎 — 쓰기 규칙이 하나 더)
  • 왼쪽 위 안내는 "무슨 일 · 손으로 할 일"만 — 짧아진다

제 추천: C. 표준 단어 버튼의 약점(버튼만 보면 무엇이 될지 모름)을 버튼 바로 밑에서 메우고, 주 버튼 자리는 지금 그대로라 손이 외운 위치가 바뀌지 않습니다. B도 설명과 버튼이 붙어 좋지만, 주 버튼 자리가 지금(가운데)에서 옮겨지고 오른쪽 정렬 두 줄은 읽기가 조금 덜 편합니다. A는 버튼이 셋일 때 안내 문장이 길어져 "지금 할 일 하나만"(DESIGN.md 톤)에서 멀어집니다.
